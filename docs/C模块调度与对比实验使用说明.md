# C模块调度与对比实验使用说明

## 1. 触发方式

C模块不会在后台自行扫描工程或自动启动性能实验。

测试人员需要通过前端按钮或API手动发起一次调度对比任务。任务发起后，FIFO基线、任务开销测量、优化调度、两种方案执行、指标计算和合同条件判断全部由系统自动完成。

推荐在前端使用一个明确的操作入口，例如：

```text
开始调度对比测试
```

对应后端接口：

```text
POST /api/v1/tasks/schedule-comparisons
```

## 2. 自动执行流程

```text
测试人员提交1～3组任务并手动启动
→ 系统按FIFO基线执行第一组任务
→ 使用FIFO实测耗时作为任务开销估计
→ 系统自动生成资源感知优化计划
→ 系统执行优化方案
→ 计算该组任务的时耗差异和改进率
→ 对剩余任务组重复上述过程
→ 计算平均改进率并判断合同指标
```

测试人员不需要分别选择FIFO和优化策略，也不需要手工启动两次实验。

## 3. 任务开销的来源

调度对比接口不要求测试人员准确填写`estimated_ms`。

FIFO第一次执行同时承担开销测量作用。系统记录每个任务的实际耗时，并使用这些实测值生成后续优化调度计划。结果中的：

```text
cost_estimation_source = FIFO_ACTUAL_DURATION
```

表示优化调度使用的是FIFO阶段的真实任务耗时。

## 4. 合同条件判断

系统只有在同时满足以下条件时，才将`meets_contract_target`标记为`true`：

1. 提交了3组测试负载。
2. 每组FIFO任务的执行时耗相对差异不低于200%。
3. FIFO和优化方案中的所有任务均执行成功。
4. 3组任务的平均改进率不低于15%。

当前时耗差异计算公式为：

```text
(最大任务耗时 - 最小任务耗时) / 最小任务耗时 × 100%
```

当前改进率计算公式为：

```text
(FIFO总耗时 - 优化方案总耗时) / FIFO总耗时 × 100%
```

如果甲方后续提供不同的书面计算口径，应以甲方确认口径为准并同步修改实现和本文档。

## 5. 范围边界

- 人工操作只负责选择测试负载并发起一次实验。
- C模块负责调度计划、核心分配和性能对比。
- A模块负责进程启动、日志、进度、超时和取消。
- C模块不会自动处理Makefile依赖修复，该能力属于B模块。
- 开发阶段的模拟任务不能作为最终验收测试代码。
